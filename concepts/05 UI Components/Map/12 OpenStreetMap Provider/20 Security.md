The Map renders **OsmTileServerConfig**.[attribution](/api-reference/10%20UI%20Components/dxMap/9%20Types/OsmTileServerConfig/attribution.md '/Documentation/ApiReference/UI_Components/dxMap/Types/OsmTileServerConfig/#attribution') and **markers[]**.**tooltip**.[text](/api-reference/10%20UI%20Components/dxMap/1%20Configuration/markers/tooltip/text.md '/Documentation/ApiReference/UI_Components/dxMap/Configuration/markers/tooltip/#text') values as HTML. If these values come from untrusted sources, encode **tooltip**.**text** and sanitize **attribution** (retain notices and links that your tile and data providers require). Refer to the following help topics for more information:

- [Potentially Vulnerable API - OsmTileServerConfig.attribution](/concepts/Common/Security%20Considerations/20%20HTML%20Encoding/30%20Potentially%20Vulnerable%20API/OsmTileServerConfig.attribution.md '/Documentation/Guide/Common/Security_Considerations/#HTML_Encoding/Potentially_Vulnerable_API/OsmTileServerConfigattribution')
- [Potentially Vulnerable API - markers[].tooltip.text](/Documentation/Guide/Common/Security_Considerations/#HTML_Encoding/Potentially_Vulnerable_API/markers[]tooltiptext)

The browser requests tiles and runs **calculateLocation** and **calculateRoute**. Users can read API keys in tile URLs and service requests. Use keys that your service allows in client applications (for instance, keys restricted to your domain). If keys must stay confidential, route requests to the map service through your server.

Add map service origins to your Content Security Policy as described in the following help topic: [CSP Directives for Map Integrations](/concepts/Common/Security%20Considerations/40%20Content%20Security%20Policy/20%20CSP%20Directives%20for%20Map%20Integrations.md '/Documentation/Guide/Common/Security_Considerations/#Content_Security_Policy/CSP_Directives_for_Map_Integrations').
